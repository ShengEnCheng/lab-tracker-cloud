把研究室系統架到雲端

這份引導會帶你從「什麼都沒有」到「自己的研究室系統上線」。 全程大約 20～30 分鐘，不需要寫程式。你只要照著每一步做，做完按「驗證」就好。

你的進度
已完成 0 / 5 步

關於你填的資料： 你填的 GitHub 帳號、網址與金鑰只存在你自己這台電腦的瀏覽器裡 （用瀏覽器的本機儲存空間），不會上傳到任何地方，也不會寫進這個網頁的檔案。 換一台電腦就要重填。用完如果不想留著，可以按左邊的「清除我填過的資料」。

第 1 步

開始之前：你會得到什麼

做完這份引導，你會有一個自己的網址（長得像 https://你的專案名稱.vercel.app）和一個自己的資料庫。 研究室成員用瀏覽器打開那個網址就能登入使用，資料存在雲端，換電腦也看得到。

你會得到

  • 一個可以傳給同事的網址
  • 一個只有你們研究室看得到的資料庫
  • 同事各自的帳號與權限
  • 每天自動備份的資料

你需要準備

  • 一個 email（用研究室的信箱最好，之後交接比較方便）
  • 一台可以上網的電腦
  • 大約 20～30 分鐘不被打斷的時間

要花錢嗎？

  • 不用。這套做法用的都是免費方案。
  • 免費方案有額度限制，但研究室的用量通常遠低於上限。
  • 唯一要注意的：資料庫連續 7 天沒人用會「睡著」 （暫停），第一次打開會慢一點。資料不會不見，第 7 步會教怎麼叫醒它。

先解釋三個會一直出現的名詞

GitHub：放程式碼的地方，可以想成「雲端的資料夾」。你會在上面放一份自己的副本。 別人動不到你的那份，你也不會動到別人的。

Vercel：把程式碼變成一個網址的服務，也就是「網站的家」。 它會幫你把網站架好、給你一個網址，還能自動更新。

Supabase：資料庫，也就是「放資料的地方」。 同事的名字、收案進度這些，都存在這裡。

這三個都是業界常用的服務，這份引導只會用到免費的部分，而且都會帶著你點。

第 2 步

建立一個 GitHub 帳號

GitHub 是放程式碼的地方。你需要一個免費帳號，這樣才能把系統複製一份到自己名下。 為什麼要自己做一份：這樣系統是你的，别人改東西不會影響到你，你也不會影響到别人。

  1. 打開 github.com/signup （會開新分頁）。 建議用研究室的 email 註冊，之後交接比較容易。
  2. 填 email、密碼、使用者名稱（username），照畫面完成註冊。 使用者名稱只能用英文、數字和減號（-），例如 my-lab。 這個名字會出現在你的網址上，註冊後可以改但很麻煩，先想好。
  3. 到信箱點 GitHub 寄來的驗證信。 沒點驗證信，帳號不算完成，下一步會驗不過。
  4. 回到這裡，在下面填入你的使用者名稱，然後按「驗證」。
是「使用者名稱」，不是 email，也不是顯示名稱。 登入 GitHub 後，右上角大頭貼旁邊那個就是。
我會去 GitHub 查這個名字存不存在，只查公開資料，不會動你的帳號。
第 3 步

把程式碼複製一份，變成你的網站

接下來按一個按鈕就好。這個按鈕會做兩件事：

  • 把程式碼複製一份到你的 GitHub 帳號（變成你自己的副本）
  • 幫你在 Vercel 建立一個網站，並給你一個網址

不會動到别人的東西，也不會覆蓋任何現有的網站。整個過程不需要你輸入任何程式碼。

按下去之後會發生什麼

  1. Vercel 會請你登入，並授權它讀寫你的 GitHub。 沒有 GitHub 帳號會先請你註冊——你上一步已經辦好了。
  2. 它會問你要把程式碼複製到哪個帳號、專案要叫什麼名字。 名字可以照預設，等等會用到這個名字組網址。
  3. 接著會請你連接 Supabase（資料庫）——這就是下一步要做的事，先照畫面點下去。
  4. 按下 Deploy，等 1～3 分鐘。完成後它會給你一個網址。

如果畫面停住或出現紅字

先看它寫什麼。最常見的是「這個專案名稱已經有人用了」——換一個名字就好 （例如加上你的研究室縮寫或今天的日期）。 如果完全看不懂，把畫面截圖，第 7 步有寫可以找誰。

進階：這個網址裡的每個參數是什麼意思

上面那個「複製網址」按鈕複製的，就是一個 Vercel 的部署網址。 它只是把幾個設定用網址傳給 Vercel，沒有任何祕密在裡面。 維護者若要換成自己的範本，改 wizard/config.js 就好。

整段複製過來，前面要有 https://。 在 Vercel 後台的專案頁面（Project）上方就找得到，或部署完成時畫面上那顆「Visit」按鈕。
我會試著連過去看你部署的網站有沒有起來。
第 4 步

建立資料庫（Supabase）

資料庫就是放資料的地方。你剛剛按「一鍵部署」時，Vercel 應該已經問過你要不要 連接 Supabase（這是官方整合，畫面會寫 Supabase）。照下面做就好。

如果你在部署時已經跳過 Supabase

沒關係，還是可以補：到 Vercel 的專案頁面 → 上方選單 Storage（或 Integrations）→ 找到 Supabase → 按 Connect。 之後的流程跟下面一樣。

  1. 在 Vercel 的部署流程中，看到 Supabase 的畫面時，按 「Create a new Supabase project」（建立新的 Supabase 專案）。 意思是「幫我開一個新的資料庫」，不是選現有的。
  2. 方案選 Free（免費）。 免費方案就夠研究室用了，之後要升級隨時可以。
  3. 區域（Region）選 Singapore（新加坡）。 離台灣最近，速度最快。選錯也可以用，但會慢一點。
  4. 按 Continue / Create，等它建立完成（大約 1～2 分鐘）。
  5. 金鑰會自動填好，不用手抄。 這是官方整合的好處：Vercel 會把「資料庫在哪」和「用哪把鑰匙」自動設定成網站的環境變數。 你不用自己複製貼上，也不會抄錯。

重要：兩種金鑰不要搞混

Supabase 有兩種金鑰（key）：

  • sb_publishable_…（可以公開的）： 這把是給網頁用的，等等我會請你貼上來驗證。它本來就會出現在網頁程式裡，貼給我不會出事。
  • sb_secret_… 或 service_role（絕對不能公開的）： 這把等於資料庫的萬能鑰匙。不要貼給任何人、不要貼進任何網頁， 包括這一個。這份引導從頭到尾都不會跟你要這把。
在 Supabase 後台左側 Settings（齒輪圖示）→ API， 找 Project URL。長得像 https://xxxx.supabase.co。 貼 /rest/v1 之類的尾巴也沒關係，我會自動去掉。
在 Supabase 後台 Settings → API Keys， 找 sb_publishable_ 開頭的那一串。 不是 sb_secret_ 開頭的那把。 這把金鑰只會存在你自己的瀏覽器裡。
我會去你的資料庫問一句「你還好嗎」，確認連得到。
第 5 步

在資料庫裡建立資料表

資料庫現在是空的，像一間剛裝潢好但沒有櫃子的房間。 這一步要把「櫃子」做好——也就是建立資料表 （表格的意思：欄位與規則）。

做法是：把下面的「建表語法」複製，貼到 Supabase 的 SQL Editor（貼程式碼的地方）跑。 這份語法分成幾段，照順序一段一段貼，每段都要按一次 RUN。 跑完就永遠有效，不用每次做。

怎麼貼？每一段都做這四個動作

  1. 打開你的 Supabase 專案後台。
  2. 左邊選單找到最下面的 SQL Editor（圖示像一張紙加 >_）。 如果選單收起來了，先按左上角的選單圖示展開。
  3. 按 New query，把第 1 段語法貼進去。 有幾段就重複幾次：每次都要先按 New query 開一個新的，再貼下一段。
  4. 按右下角的 RUN（或按 ⌘+Enter / Ctrl+Enter）。

要貼的建表語法

跑完應該看到什麼

畫面下方會出現 「Success. No rows returned」（成功，沒有回傳資料列）。 這是正常的——建資料表不會產生資料。 如果出現紅字錯誤，通常是：(1) 貼上的內容被截斷了、 (2) 你貼到別的專案去了。把紅字截圖，第 7 步有寫可以找誰。

進階：這段語法到底做了什麼

簡單說，它建立了六個資料表，並設好「誰能看、誰能改」的規則。 第 1 段處理實驗資料本身：

  • lab_state：全部實驗資料都存在這裡（只有一列）。
  • lab_profiles：成員帳號與角色（誰是管理員、誰是一般研究者）。
  • lab_audit_logs：誰在什麼時候改了什麼（稽核紀錄）。
  • lab_backups、lab_backup_runs：備份與備份紀錄。

第 2 段建立 lab_settings：只存研究室的顯示設定（名稱、代碼、聯絡信箱）， 讓登入畫面在「還沒登入」時也能顯示研究室叫什麼名字。

另外它開了 RLS（列級權限）——意思是「沒登入的人看不到資料」。 所以等等驗證時，就算資料表建好了，查詢也會回一個空陣列，這是正常的。

我會去你的資料庫問「有沒有一個叫 lab_state 的資料表」。
第 6 步

建立你自己的管理員帳號

最後一步了。打開你的網站，會看到一個「第一次使用」的設定畫面， 填完就完成了。

  1. 打開你剛剛貼上的網址（點這裡開啟我的網站）。還沒填網址的話，先回第 3 步填好，這個連結才會生效。 也可以直接複製第 3 步填的網址，貼到瀏覽器打開。
  2. 應該會看到「第一次使用」的設定畫面。 如果看到的是登入畫面（要你輸入 email 和密碼），代表已經有人設定過了，跳到第 7 步。
  3. 填四個欄位：
    • 研究室名稱：例如「認知神經科學研究室」。之後畫面上會顯示這個名字。
    • 你的名字：你自己的稱呼。
    • email：之後登入要用，建議用研究室的信箱。
    • 密碼：至少 8 個字元。請記下來，這把是管理員的密碼。
  4. 按送出 / 建立。成功的話會直接進入系統，你就變成管理員了。

這組帳號很重要

這是管理員帳號，可以新增同事、改資料、還原備份。 請用一個你會長期收信的 email，密碼也請好好保管（用密碼管理器更好）。 之後同事的帳號由你在系統裡建立，他們不用自己去註冊。

之後誰負責

  • 你：管理員，管帳號與資料。
  • Vercel / Supabase：網站與資料庫的房東（免費方案）。
  • 要改畫面或加功能：第 7 步下面的常見問題有寫。

自動更新（多半可以跳過）

你的網站會每天自己檢查一次有沒有新版（修正錯誤、安全性更新）， 有就裝上去。你的資料不會被動到。

如果你們不想讓它自己更新，登入系統後打開「⚙️ 系統設定」， 把「自動更新」關掉就好。

建議順手做這一步，開關才會生效： 到 GitHub 你的 repo → Settings → Secrets and variables → Actions → Variables → New repository variable，名稱填 LAB_SITE_URL，值填你的網站網址 （你的網址）。 只做一次，之後不用再管。

沒填也不會壞，只是上面那個「系統設定」裡的開關不會有作用 （更新會照常進行）。

常見問題

網站打不開，或第一次打開等很久 / 資料庫睡著了怎麼辦？

Supabase 免費方案有一個規則：連續 7 天完全沒人使用，資料庫會暫停（睡著）。 這段時間網站會打不開或轉很久。

怎麼叫醒它：

  1. 登入 supabase.com/dashboard。
  2. 點進你的專案。如果它睡著了，畫面上方會出現 Restore project（或 Resume）的按鈕。
  3. 按下去，等幾分鐘。它會自己醒過來。

資料不會不見。暫停只是關機，不是刪除。

想避免它睡著：平常有人在用就不會睡。如果研究室會放長假，回來第一次打開前先去叫醒它就好。

要怎麼備份？資料會不會不見？

這套系統有三層保險：

  • 每天自動備份：系統每天早上會自動把資料快照存進資料庫 （由 Vercel 的排程觸發，設定在 vercel.json）。 會保留最近 30 天的每日備份，另外保留 12 週的每週備份。
  • 系統內可以手動備份與還原：管理員在系統裡就能按「立即備份」， 出事時也能從清單選一個時間點還原。改資料前系統也會自動先存一份。
  • 自己再存一份更安心：系統有「匯出」功能，可以把全部資料下載成一個檔案， 存到研究室的雲端硬碟（例如 Google Drive）或外接硬碟。 建議每學期末做一次，這是唯一連「資料庫整個被刪掉」都能救回來的方法。

還原的時候要注意：還原會把資料「倒回」到那個時間點， 之後新增的資料會被蓋掉（但系統會先幫你存一份還原前的快照，所以也不會真的消失）。

想改畫面、加功能，或系統壞了要找誰？

這套系統的程式碼就在你自己的 GitHub 帳號裡， 所以你有完整的控制權，不是被某家公司綁住。

三種情況，三種做法：

  • 只是要調文字或顏色：可以請懂網頁的人改 GitHub 上的檔案， 存檔後 Vercel 會自動更新網站（約 1～2 分鐘）。
  • 要加新功能：把需求寫清楚（誰要用、要解決什麼問題、大概長怎樣）， 交給原本協助建置的人，或任何會寫網頁的工程師。他們看 GitHub 上的程式碼就能接手。
  • 系統壞了、資料怪怪的：先不要動資料。 把出問題的畫面截圖（包含網址與時間），再找人看。 如果只是資料顯示不對，可以先用「還原」回到上一個正常的時間點。

交接的時候，記得把三樣東西交出去：這份引導、GitHub 帳號、Supabase 專案的管理權限。 這樣下一個人才能接手。

我可以改網址嗎？

可以，但先不要急。Vercel 免費方案給的網址（xxx.vercel.app） 就可以直接用了。

如果你們研究所有自己的網域（例如 lab.example.edu.tw）， 可以在 Vercel 的專案設定 → Domains 加上去。這需要請網域的管理員改一筆 DNS 紀錄， 建議請資訊人員協助。

換網址之後，原本的 xxx.vercel.app 還是可以用，不會斷。

要付錢嗎？之後會不會被收費？

這套做法只用免費方案：Vercel 的 Hobby（個人免費）方案 + Supabase 的 Free（免費）方案。 只要不主動升級、不绑信用卡，就不會被收費。

免費方案的額度對研究室規模的用量來說通常很夠。如果真的超出， 網站會先暫停而不是自動扣款，會通知你去處理。

要注意的是：Vercel 的免費方案規定是「個人、非商業用途」。研究室的內部管理系統通常沒問題， 但如果要當成正式的對外服務，建議先確認一下他們的條款。

這份引導網頁是純靜態檔案，不需要網路也能打開（但要驗證時當然需要網路）。 你填的資料只存在你自己的瀏覽器裡。整份引導沒有任何金鑰或密碼寫在檔案中。
