# 部署指南：建立你們研究室的追蹤系統

這份文件帶你從零開始，建立一套屬於你們研究室的系統。

**不需要會寫程式。** 全程在瀏覽器裡完成，大約 30 分鐘。

---

## 開始之前

### 你會需要

| 項目 | 說明 |
|---|---|
| 一個 Email | 建議用研究室的共用信箱，或老師的信箱。之後用這個登入 |
| 一台電腦、瀏覽器 | Chrome、Edge、Safari 都可以 |
| 30 分鐘 | 中間要等幾次「建立中」，可以先去泡杯咖啡 |

### 不用擔心的事

- **不用付錢**：下面的服務都有免費方案，這套系統在免費額度內就夠用
- **不用裝任何軟體**：全部在網頁上做
- **不會弄壞任何東西**：每一步失敗都可以重來

### 這套系統長什麼樣子

```
你的瀏覽器
    ↓
Vercel（放網站的地方）        ← 別人打網址就連到這裡
    ↓
Supabase（放資料的地方）      ← 你們的資料存在這裡，只有你們看得到
```

兩個服務都要申請，都免費。資料在 Supabase，網站程式在 Vercel —— 分開放的，
所以更新程式不會動到資料。

---

## 步驟 0：拿到引導網頁

維護者會給你一個網址，打開它就會看到引導畫面。

> **維護者注意**：給出網址之前，先確認範本 repo 已經建立、是 public，
> 而且 `wizard/config.js` 的 `repoUrl` 指向它。沒有的話，助理做到第 3 步
> 「一鍵部署」時 Vercel 會找不到程式碼，錯誤訊息完全看不懂。
> 詳見 [handover.md](handover.md) 的「交接清單」。

如果沒有網址，請維護者把 `wizard/index.html` 這個檔案傳給你，用瀏覽器打開即可
（這個頁面不需要網路就能運作，它只是幫你產生連結）。

> **為什麼要有引導網頁？**
> 因為申請這些服務的流程有很多小細節（要選哪個方案、金鑰在哪個頁面、
> 網址要貼在哪一格）。引導網頁把每一步的連結、該複製的文字、該貼的位置
> 都準備好，並且在你做完之後立刻檢查對不對。

---

## 步驟 1：申請 GitHub 帳號

GitHub 是放程式碼的地方。你的研究室會有自己的一份副本。

### 做什麼

1. 點引導網頁第 2 步的連結（<https://github.com/signup>）
2. 用**研究室的 Email** 註冊
3. 設定密碼、驗證 Email

### 要注意

- 用研究室的信箱註冊，不要用個人的 —— 這樣之後交接才不會卡住
- 免費方案就夠了
- 記下你用的帳號密碼，之後會用到

### 通過的標準

引導網頁會顯示 ✅。你也可以自己確認：能登入 <https://github.com> 就好。

---

## 步驟 2：申請 Supabase 帳號並建立資料庫

Supabase 是放資料的地方。你們的個案資料、成員名單都存在這裡。

### 做什麼

1. 點引導網頁第 4 步的連結（<https://supabase.com/dashboard/sign-up>）
2. **用同一個 GitHub 帳號登入**（最快的方式）
3. 按 **New project**
4. 填寫：
   - **Name**：`lab-tracker`（或任何你認得的名字）
   - **Database Password**：按「Generate a password」讓它產生，**然後複製下來存好**
   - **Region**：選 **Southeast Asia (Singapore)** —— 離台灣最近，速度最快
5. 按 **Create new project**，等 2 到 3 分鐘

### 要注意

**資料庫密碼要存起來。** 這把密碼平常不會用到（系統用的是另外的金鑰），
但未來如果要直接操作資料庫會需要。存到你們研究室共用的密碼管理工具裡。

### 通過的標準

引導網頁會檢查你是否已經建立專案。你也可以自己看：Supabase 後台左側看得到
你的專案名稱，狀態是綠色的 `Active`。

---

## 步驟 3：建立資料表

這一步是把「表格的格式」建到資料庫裡。**要貼三段語法，順序不能顛倒。**

### 做什麼

1. 在 Supabase 後台，左側選單最下方點 **SQL Editor**
2. 點 **New query**
3. 回到引導網頁第 5 步，按「複製第一段」
4. 貼到 Supabase 的編輯器裡，按右下角的 **Run**（或 `Ctrl/Cmd + Enter`）
5. 看到 `Success. No rows returned` 就是成功
6. **點 New query 再開一個新的**，按「複製第二段」，貼上，按 **Run**
7. **再開第三個新的**，按「複製第三段」，貼上，按 **Run**

### 為什麼要三段

- **第一段**建立主要的資料表（個案、成員、備份記錄）與權限函式。
- **第二段**建立研究室的設定表（研究室名稱、設定完成時間）。它要用到第一段建立的權限函式，所以必須在後面。
- **第三段**在設定表上補一個「自動更新」的欄位，讓研究室的介面上可以關掉自動更新。它要修改第二段建立的表，所以必須最後跑。

### 已經部署過的研究室

如果你之前已經跑過第一、二段，**只要補跑第三段就好**，不用重跑前面。
重跑也不會壞（每段都寫成可以重複執行），但沒必要。

### 要注意

- **三段都要跑。** 只跑第一段的話，系統會停在「資料表還沒建立完成」；
  只跑到第二段而漏了第三段，系統可以用，但「系統設定」裡的自動更新開關
  會顯示資料庫還缺欄位，無法切換。
- 如果出現紅色錯誤，通常是因為已經跑過了 —— 可以直接跳過繼續
- 貼上時不要漏掉最後的分號

### 通過的標準

引導網頁會自動檢查資料表建好了沒。你也可以自己確認：
Supabase 左側 **Table Editor** 裡應該看得到 `lab_state`、`lab_profiles`、
`lab_settings` 這幾張表。

## 步驟 4：部署到 Vercel

Vercel 負責把網站跑起來，讓別人可以連進來。

### 做什麼

1. 點引導網頁第 3 步的按鈕（**Deploy to Vercel**）
2. 用**同一個 GitHub 帳號**登入 Vercel
3. 第一次用會要求授權 Vercel 讀取你的 GitHub —— 按 **Authorize**
4. 填寫專案名稱（例如 `cog-neuro-lab`），按 **Create**
5. 等 1 到 2 分鐘部署完成

### 要注意

- 專案名稱會變成你的網址，用小寫英文與減號（例如 `cog-neuro-lab`）
- 免費方案（Hobby）就夠用
- 部署完會給你一個網址，長得像 `https://cog-neuro-lab.vercel.app`

### 通過的標準

引導網頁會確認你的網址活著。你也可以自己開那個網址看看 ——
應該會看到「還不能開始使用」（因為還沒填金鑰，這是正常的）。

---

## 步驟 5：填入金鑰

這一步把 Vercel（網站）和 Supabase（資料庫）接起來。

### 做什麼

1. 回到 Supabase 後台，左側選單最下方點 **Project Settings**（齒輪圖示）
2. 點 **API Keys**
3. 你會看到兩把金鑰，各自複製：

| 複製哪一把 | 貼到 Vercel 的哪個變數 |
|---|---|
| **Project URL**（`https://xxxx.supabase.co`） | `SUPABASE_URL` |
| **Publishable key**（`sb_publishable_…`） | `SUPABASE_PUBLISHABLE_KEY` |
| **Secret key**（`sb_secret_…`） | `SUPABASE_SECRET_KEY` |

> **舊稱呼**：如果你的 Supabase 顯示的是 `anon` 和 `service_role`，
> 那就是舊版名稱。`anon` → `SUPABASE_PUBLISHABLE_KEY`，
> `service_role` → `SUPABASE_SECRET_KEY`。兩種都可以用。

4. 到 Vercel 專案 → **Settings** → **Environment Variables**
5. 把上面三個變數一個一個加進去（Name 填左邊、Value 貼右邊），
   Environment 三個都勾（Production、Preview、Development）
6. 加完之後到 **Deployments** 頁籤，最新的那一筆右邊點 **⋯** → **Redeploy**

### 要注意

**這三把金鑰的差別很重要：**

- `SUPABASE_URL` 和 `SUPABASE_PUBLISHABLE_KEY` 會被送到使用者的瀏覽器 —— 這是正常的，
  它們的權限很低，讀不到任何資料
- `SUPABASE_SECRET_KEY` **可以繞過所有權限規則**。它只能放在 Vercel 的環境變數裡，
  絕對不要貼到任何公開的地方、不要傳到群組、不要寫進程式碼

### 通過的標準

Redeploy 完成後，打開你的網址，應該從「還不能開始使用」變成
**「歡迎使用研究室追蹤系統」** 的設定畫面。

---

## 步驟 6：建立你的研究室

### 做什麼

1. 打開你的網址（`https://你的專案名.vercel.app`）
2. 填寫：
   - **研究室名稱**：會顯示在畫面最上方，例如「認知神經科學研究室」
   - **研究室代碼**：選填，例如 `CNC`
   - **你的姓名**
   - **你的登入 Email**：建議用步驟 1 申請的那個
   - **密碼**：至少 8 個字元，要同時有英文字母和數字
3. 「先放一些示範資料」預設打勾 —— 建議留著，你可以先看看系統長什麼樣子，
   之後可以一鍵清空
4. 按 **建立我的研究室**

### 通過的標準

看到「設定完成了」的畫面，按「開始使用」後用剛剛的 Email 與密碼登入，就進到系統了。

---

## 步驟 7：加入同事

1. 登入後點右上角 **👥 人員名冊**
2. 按 **新增成員**
3. 填姓名、Email、角色
4. 系統會產生一組**臨時密碼**，複製給那位同事（只會顯示這一次）

### 四種角色的差別

| 角色 | 可以做什麼 |
|---|---|
| **主持人（admin）** | 全部功能，包含管理成員 |
| **研究管理（study_manager）** | 管理個案與研究案、建立備份 |
| **研究助理（researcher）** | 查看與更新自己負責的個案 |
| **備份管理（backup_admin）** | 管理備份與還原 |

## 每天怎麼用

1. 打開網址，用 Email 與密碼登入
2. 左邊三個頁籤：
   - **收案待辦**：誰該做什麼、哪些已經逾期
   - **月曆**：這個月的收案排程
   - **研究個案管理**：所有個案的詳細資料
3. 改了任何東西會自動儲存

## 常見問題

### 網站打開說「還不能開始使用」

分兩種情況，畫面上會寫：

- **「還沒連上資料庫」** → 回到步驟 5，確認 Vercel 的三個環境變數都在，而且有按 Redeploy
- **「資料表還沒建立」** → 回到步驟 3，把第二段語法也貼進 SQL Editor 執行

### 過了一個寒假回來，網站打不開

Supabase 免費方案**閒置一週會自動暫停**專案（資料不會消失）。

修法：登入 Supabase，左側會看到專案標示 `Paused`，點 **Restore project**，
等一兩分鐘就好了。

想避免這個問題：Pro 方案（每月 $25 起）不會因閒置暫停。

### 忘記管理員密碼

目前沒有「忘記密碼」的自動流程。請維護者在 Supabase 後台重設：

1. Supabase → **Authentication** → **Users**
2. 找到那個 Email，右邊 **⋯** → **Reset password**

### 同事說連不上

1. 確認你給的網址是 `https://` 開頭的那個（Vercel 給的 Production 網址）
2. 確認那位同事已經在「人員名冊」裡、而且狀態是啟用
3. 如果是剛加入的，請他重新整理頁面再登入

### 想把示範資料清掉

示範資料的個案編號都以 `DEMO` 開頭，一眼就分得出來。
在「研究個案管理」頁籤可以逐筆刪除，或匯入一份空的資料覆蓋。

### 兩個人同時改同一筆資料

系統會擋下後儲存的那個人，並自動重新載入最新資料、提示「請再按一次儲存」。
你打的內容不會消失，再按一次就好。

### 想備份

到右上角 **備份** 頁籤，按 **建立備份**。也可以開啟自動備份（每天一次）。

## 要交給下一個人時

1. 確認他已經被加入「人員名冊」，角色是**主持人**
2. 把這份文件給他
3. 交接這些帳號的擁有權（都在實驗室信箱下，所以直接用實驗室信箱登入即可）：
   - GitHub（程式碼）
   - Supabase（資料庫）
   - Vercel（網站）

**建議都用實驗室共用信箱註冊**，這樣人員離開時不用轉移任何東西。
