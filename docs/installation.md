# 部署指南：建立你們研究室的追蹤系統

這份文件帶你從零開始，建立一套屬於你們研究室的系統。

**不需要會寫程式。** 全程在瀏覽器裡完成，大約 30 分鐘。

---

## 開始之前

### 你會需要

| 項目 | 說明 |
|---|---|
| 一個 Email | 建議用研究室的共用信箱，或老師的信箱。之後用這個登入 |
| 一台電腦、瀏覽器 | Chrome、Edge、Safari 都可以 |
| 30 分鐘 | 中間要等幾次「建立中」，可以先去泡杯咖啡 |

### 不用擔心的事

- **不用付錢**：下面的服務都有免費方案，這套系統在免費額度內就夠用
- **不用裝任何軟體**：全部在網頁上做
- **不會弄壞任何東西**：每一步失敗都可以重來

### 這套系統長什麼樣子

```
你的瀏覽器
    ↓
Vercel（放網站的地方）        ← 別人打網址就連到這裡
    ↓
Supabase（放資料的地方）      ← 你們的資料存在這裡，只有你們看得到
```

兩個服務都要申請，都免費。資料在 Supabase，網站程式在 Vercel —— 分開放的，
所以更新程式不會動到資料。

## 步驟 0：拿到引導網頁

維護者會給你一個網址，打開它就會看到引導畫面。

> **維護者注意**：給出網址之前，先確認範本 repo 已經建立、是 public，
> 而且 `wizard/config.js` 的 `repoUrl` 指向它。沒有的話，助理做到第 4 步
> 「一鍵部署」時 Vercel 會找不到程式碼，錯誤訊息完全看不懂。
> 詳見 [handover.md](handover.md) 的「交接清單」。

如果沒有網址，請維護者把 `wizard/index.html` 這個檔案傳給你，用瀏覽器打開即可
（這個頁面不需要網路就能運作，它只是幫你產生連結）。

> **為什麼要有引導網頁？**
> 因為申請這些服務的流程有很多小細節（要選哪個方案、金鑰在哪個頁面、
> 網址要貼在哪一格）。引導網頁把每一步的連結、該複製的文字、該貼的位置
> 都準備好，並且在你做完之後立刻檢查對不對。

## 步驟 1：申請 GitHub 帳號

GitHub 是放程式碼的地方。你的研究室會有自己的一份副本。

### 做什麼

1. 點引導網頁第 2 步的連結（<https://github.com/signup>）
2. 用**研究室的 Email** 註冊
3. 設定密碼、驗證 Email

### 要注意

- 用研究室的信箱註冊，不要用個人的 —— 這樣之後交接才不會卡住
- 免費方案就夠了
- 記下你用的帳號密碼，之後會用到

### 通過的標準

引導網頁會顯示 ✅。你也可以自己確認：能登入 <https://github.com> 就好。

## 步驟 2：申請 Supabase 帳號並建立資料庫

Supabase 是放資料的地方。你們的個案資料、成員名單都存在這裡。

**這一步在部署之前**——先建好資料庫，下一步部署時才有三個值可以填。

> **為什麼不是「部署時順便建」？** Vercel 的一鍵部署有個選項可以在部署時
> 順便開一個 Supabase 專案，但全新的 Supabase 帳號會卡在那裡：Vercel 會說
> 「找不到你的 Supabase 組織」，然後整個流程停住，連跳過都沒得按。
> 先自己建好，多花兩分鐘，但不會卡住。

### 做什麼

1. 點引導網頁第 3 步的連結（<https://supabase.com/dashboard/sign-up>）
2. **用同一個 GitHub 帳號登入**（最快的方式）
   - 第一次登入如果問你要不要建立「組織（organization）」，就建一個。
     組織只是「把專案放在一起的資料夾」，免費方案就夠用。
3. 按 **New project**
4. 填寫：
   - **Name**：`lab-tracker`（或任何你認得的名字）
   - **Database Password**：按「Generate a password」讓它產生，**然後複製下來存好**
   - **Region**：選 **Southeast Asia (Singapore)** —— 離台灣最近，速度最快
5. 按 **Create new project**，等 2 到 3 分鐘
6. 建好之後，左側選單最下面 **Project Settings**（齒輪）→ **API Keys**，
   這裡有三個值，下一步會用到

### 三個值，兩個可以公開、一個不行

| 你在後台看到 | 之後要填的變數 | 能不能公開 |
|---|---|---|
| **Project URL**（`https://xxxx.supabase.co`） | `SUPABASE_URL` | 可以 |
| **Publishable key**（`sb_publishable_…`） | `SUPABASE_PUBLISHABLE_KEY` | 可以 |
| **Secret key**（`sb_secret_…`） | `SUPABASE_SECRET_KEY` | **絕對不行** |

> **舊稱呼**：如果顯示的是 `anon` 和 `service_role`，就是舊版名稱。
> `anon` → `SUPABASE_PUBLISHABLE_KEY`，`service_role` → `SUPABASE_SECRET_KEY`。

**Secret key 等於資料庫的萬能鑰匙**，可以繞過所有權限規則。它只能填進
Vercel 的環境變數，絕對不要貼到任何公開的地方、不要傳到群組、不要寫進程式碼。

### 要注意

**資料庫密碼要存起來。** 這把密碼平常不會用到（系統用的是上面那三把金鑰），
但未來如果要直接操作資料庫會需要。存到你們研究室共用的密碼管理工具裡。

**現在就把 Secret key 複製起來放著。** 下一步部署時要貼進表單，
中間不要離開那一頁免得找不到（或者記住它在哪：Settings → API Keys）。

### 通過的標準

引導網頁會檢查資料庫連得到。你也可以自己看：Supabase 後台左側看得到
你的專案名稱，狀態是綠色的 `Active`。

## 步驟 3：建立資料表

這一步只有一個動作：**把整份語法複製起來，貼進 Supabase 的 SQL Editor，按一次 RUN。**

### 做什麼

1. 在 Supabase 後台，左側選單最下方點 **SQL Editor**
2. 點 **New query**
3. 回到引導網頁第 4 步（建立資料表），按 **「複製整份語法」**
4. 貼到 Supabase 的編輯器裡，按右下角的 **Run**（或 `Ctrl/Cmd + Enter`）
5. 看到 `Success. No rows returned` 就是成功

這樣就結束了。不用開新 query、不用分次貼。

### 為什麼是整份一次貼

這份語法內部其實有四段，而且**有依賴順序**（後面的段要用到前面建的函式與資料表）。
整份貼在一起，PostgreSQL 會自己照順序跑完。

分段貼的風險是「漏掉後面幾段」——而**漏掉不會有任何錯誤訊息**，系統看起來完全正常：
- 漏掉第三段：「系統設定」裡的自動更新開關會按不動
- 漏掉第四段（權限的安全修正）：被停用的成員或陌生人有機會清光備份、覆蓋資料

引導網頁第 4 步的驗證會檢查這兩件事，但最好的做法還是根本不要分段貼。

### 已經部署過的研究室

直接**重貼整份**就好。每一段都寫成可以重複執行（`if not exists`、`create or replace`），
貼兩次不會壞、也不會動到既有資料。

**2026-11 之前部署的研究室請務必重貼一次**：第四段是權限的安全修正。
沒補的話，管理員登入後「系統設定」頁會出現黃色提醒。

### 要注意

- **貼上被截斷**是最常見的失敗原因。整份語法有兩萬多個字元，
  複製時要確認全選到了（引導網頁上有顯示字元數可以比對）。
  出現紅字錯誤時，按 **New query** 開一個乾淨的再貼一次。
- 跑完之後，資料表是空的、而且**沒登入的人讀不到任何一列**（RLS 權限規則）。
  這是正常的，驗證時看到空陣列不代表失敗。

## 步驟 4：部署到 Vercel（順便把四個值填進去）

Vercel 負責把網站跑起來，讓別人可以連進來。
這一步同時把網站和資料庫接起來 —— 部署表單會直接問你那三個值，外加一組保護備份的密碼。

### 做什麼

1. 點引導網頁第 5 步（部署網站）的按鈕（**Deploy to Vercel**）
2. 用**同一個 GitHub 帳號**登入 Vercel
3. 第一次用會要求授權 Vercel 讀取你的 GitHub —— 按 **Authorize**
4. 填寫專案名稱（例如 `cog-neuro-lab`）
5. **填四個環境變數**——這是重點，清單會直接出現在表單上：

   | 名稱 | 值 |
   |---|---|
   | `SUPABASE_URL` | 步驟 2 的 Project URL |
   | `SUPABASE_PUBLISHABLE_KEY` | 步驟 2 的 Publishable key |
   | `SUPABASE_SECRET_KEY` | 步驟 2 的 Secret key |
   | `CRON_SECRET` | 引導網頁自動產生的一串亂數（保護每日備份用） |

   引導網頁第 5 步有一張表，除了 Secret key 以外都有複製按鈕，直接按就好。

6. 按 **Deploy**，等 1 到 2 分鐘

### 為什麼要在部署時填

環境變數是**部署時**才讀進去的。如果部署完才到 Settings 補，網站不會自己知道，
一定要再按一次 Redeploy 才會生效 —— 很多人卡在這一步，因為「填了但沒用」。

在部署前填就沒有這個問題：網站建起來的當下就是完整可用的。

### 要注意

- 專案名稱會變成你的網址，用小寫英文與減號（例如 `cog-neuro-lab`）
- 免費方案（Hobby）就夠用
- **`CRON_SECRET` 不用記也不用存**，貼進 Vercel 就好。沒設的話備份照樣會跑，
  但任何人都能觸發備份、把舊的備份擠掉（系統只留最近 30 份）
- **Supabase 那三個值一個都不能少**。少了 `SUPABASE_SECRET_KEY`，網站連得動資料庫，
  但「第一次設定」那一步會壞掉，而且錯誤訊息一樣是「還沒連上資料庫」——
  完全指錯方向，很難查

### 通過的標準

引導網頁會確認兩件事：網址活著，而且**網站連得到資料庫**。
你也可以自己開那個網址看看 —— 應該會看到 **「歡迎使用研究室追蹤系統」**
的設定畫面（不是「還不能開始使用」）。

如果看到「還不能開始使用」，按引導網頁第 4 步的「檢查網站連上了沒」，
它會告訴你缺什麼、以及怎麼補。最常見的原因是某個變數填錯或漏填。

## 步驟 5：建立你的研究室

### 做什麼

1. 打開你的網址（`https://你的專案名.vercel.app`）
2. 填寫：
   - **研究室名稱**：會顯示在畫面最上方，例如「認知神經科學研究室」
   - **研究室代碼**：選填，例如 `CNC`
   - **你的姓名**
   - **你的登入 Email**：建議用步驟 1 申請的那個
   - **密碼**：至少 8 個字元，要同時有英文字母和數字
3. 「先放一些示範資料」預設打勾 —— 建議留著，你可以先看看系統長什麼樣子，
   之後可以一鍵清空
4. 按 **建立我的研究室**

### 通過的標準

看到「設定完成了」的畫面，按「開始使用」後用剛剛的 Email 與密碼登入，就進到系統了。

### 建議順手做：關掉 Supabase 的「自行註冊」

這套系統的成員帳號都由管理員在系統裡建立，不需要讓外人自己註冊。
到 Supabase 專案 → **Authentication** → **Sign In / Providers**，
把 **Allow new users to sign up** 關掉，按 **Save**。

關掉之後，管理員在系統裡新增成員還是照常運作。這是多一道保險：
就算以後有權限設定出錯，陌生人也沒辦法先註冊一個帳號來試。

## 步驟 6：加入同事

1. 登入後點右上角 **👥 人員名冊**
2. 按 **新增成員**
3. 填姓名、Email、角色
4. 系統會產生一組**臨時密碼**，複製給那位同事（只會顯示這一次）

### 四種角色的差別

| 角色 | 可以做什麼 |
|---|---|
| **主持人（admin）** | 全部功能，包含管理成員 |
| **研究管理（study_manager）** | 管理個案與研究案、建立備份 |
| **研究助理（researcher）** | 查看與更新自己負責的個案 |
| **備份管理（backup_admin）** | 管理備份與還原 |

## 每天怎麼用

1. 打開網址，用 Email 與密碼登入
2. 左邊三個頁籤：
   - **收案待辦**：誰該做什麼、哪些已經逾期
   - **月曆**：這個月的收案排程
   - **研究個案管理**：所有個案的詳細資料
3. 改了任何東西會自動儲存

## 常見問題

### 網站打開說「還不能開始使用」

分兩種情況，畫面上會寫：

- **「還沒連上資料庫」** → 回到步驟 4，確認 Vercel 的三個環境變數都在。如果部署之後才補的，一定要按 Redeploy 才會生效
- **「資料表還沒建立」** → 回到步驟 3，把整份語法貼進 SQL Editor 按一次 RUN

### 過了一個寒假回來，網站打不開

Supabase 免費方案**閒置一週會自動暫停**專案（資料不會消失）。

修法：登入 Supabase，左側會看到專案標示 `Paused`，點 **Restore project**，
等一兩分鐘就好了。

想避免這個問題：Pro 方案（每月 $25 起）不會因閒置暫停。

### 忘記管理員密碼

目前沒有「忘記密碼」的自動流程。請維護者在 Supabase 後台重設：

1. Supabase → **Authentication** → **Users**
2. 找到那個 Email，右邊 **⋯** → **Reset password**

### 同事說連不上

1. 確認你給的網址是 `https://` 開頭的那個（Vercel 給的 Production 網址）
2. 確認那位同事已經在「人員名冊」裡、而且狀態是啟用
3. 如果是剛加入的，請他重新整理頁面再登入

### 想把示範資料清掉

示範資料的個案編號都以 `DEMO` 開頭，一眼就分得出來。
在「研究個案管理」頁籤可以逐筆刪除，或匯入一份空的資料覆蓋。

### 兩個人同時改同一筆資料

系統會擋下後儲存的那個人，並自動重新載入最新資料、提示「請再按一次儲存」。
你打的內容不會消失，再按一次就好。

### 想備份

到右上角 **備份** 頁籤，按 **建立備份**。也可以開啟自動備份（每天一次）。

## 要交給下一個人時

1. 確認他已經被加入「人員名冊」，角色是**主持人**
2. 把這份文件給他
3. 交接這些帳號的擁有權（都在實驗室信箱下，所以直接用實驗室信箱登入即可）：
   - GitHub（程式碼）
   - Supabase（資料庫）
   - Vercel（網站）

**建議都用實驗室共用信箱註冊**，這樣人員離開時不用轉移任何東西。
